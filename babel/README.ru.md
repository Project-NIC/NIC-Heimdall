# Babel — преобразователь протоколов

[English](README.md) · [Čeština](README.cs.md) · **Русский**

> **Концепция на стадии проектирования — ничего не построено.** Цифры проверяются по даташитам и самим компонентам, прежде чем будет сделана плата.

**Babel ставит на ветвь ModBus датчик, который не продаётся как блок Modbus.** Собственный
интерфейс датчика — I²C, SPI, UART или 1-Wire — входит с одной стороны; с другой выходит Modbus RTU,
и хост читает готовое число в принятом в проекте формате регистров. Плата одна и та же для любого
датчика; меняется профиль прошивки, скомпилированный под конкретную позицию.

**Никакая чужая шина не ездит по станции.** Датчик, который не говорит на Modbus, преобразуется у
датчика, на этой плате, и никогда не тянется через всю станцию, чтобы его распутывали на дальнем
конце.

**Универсальна не плата, а процессор.** Плата, которая несёт драйвер для каждого датчика, никогда не
бывает закончена, поэтому эта не несёт ни одного: это `STM32H523` с выведенной периферией — SPI до
2²⁶ bit/s, USART до 2²³ baud, I²C, тактовый выход, 59 свободных выводов — на том же кварце и той же
понижающей ячейке, что и каждая плата H523 на станции, и строитель настраивает её под один датчик.
Базовая прошивка работает, даже когда ничего не подключено: плата отвечает на шине своей
идентификацией, своим штатным блоком данных и нулями, а к этому добавляется профиль для каждого
установленного датчика.

| | |
|---|---|
| класс | собственный MOD — ведомое устройство Modbus RTU на ветви **Palatine**; варианта для NodBus нет |
| код типа | **нет.** Каждая занятая позиция отвечает как отдельное ведомое устройство с типом **своей величины**, `TYPE«2 \| NUMBER`; `0xFF01 IDENT` сообщает, что эти ведомые — одна плата. **Плата без установленных датчиков отвечает один раз на ModBus тип 4, голая**, со своей идентификацией и нулями (`MODBUS.md`) |
| позиции | до **четырёх** датчиков, по одному адресу на каждый |
| интерфейсы датчиков | I²C · SPI · UART · 1-Wire · 2× GPIO · тактовый выход, всё 3,3 V |
| MCU | `STM32H523VE`, LQFP100 |
| питание | изолированные 12 V ветви по четырёхпроводному кабелю, как у покупного датчика; плата делает свои 3,3 V на `LMR43610` |
| входной каскад линии | `THVD1450`, базовый набор на плате (`HARDWARE.md`) |
| прошивка | штатный движок MOD и по одному профилю на каждый установленный датчик (`FIRMWARE.md`) |

## Структурная схема

```
   the ModBus arm — A · B · 12 V · GND
        │
   ┌────┴────────────────────────────────────────┐
   │ BABEL — H523 · LMR43610 → 3,3 V             │──▶ I²C · SPI · UART · 1-Wire · 2× GPIO · a clock ──▶ up to four sensors
   │ THVD1450 · 2× 10 Ω + SM712 · 2× 5.0SMDJ18A  │    one ModBus address per fitted position,
   └─────────────────────────────────────────────┘    0xFF01 IDENT says they are one board
```
