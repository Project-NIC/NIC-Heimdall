# Handset — помощник станции для пусконаладки и обслуживания (BLE)

[English](README.md) · [Čeština](README.cs.md) · **Русский**

Помощник для пусконаладки без ноутбука для **Mayak**, центрального блока станции (`../FIRMWARE.md` §10, сервисное окно). Вы собираете станцию, нажимаете на Mayak кнопку ввода в эксплуатацию, открываете это приложение, и оно показывает, **кто зарегистрировался** и **какой датчик не настроен / неисправен, по имени**, — **GO / NO-GO**, которое читается на телефоне. Оно также умеет отправлять команды **настройки / повторного ввода в эксплуатацию** (provision / re-commission).

> **Концепция на стадии проектирования — приложение не написано.** Этот файл — описание приложения и GATT-контракта, который соблюдает Mayak; приложение строится по нему, как только прошивка Mayak откроет описанный ниже контракт.

**Стек — рекомендация, а не требование:** одна кодовая база для Android **и** iOS — Flutter с `flutter_blue_plus` в роли BLE central — проработанный вариант; React Native с `react-native-ble-plx` или нативные Kotlin и Swift делают то же самое. BLE, а не классический BT: низкое потребление, и ESP32-S31 в Mayak всё равно поддерживает только BLE (BT 5.4 LE).

## GATT-контракт — прошивка Mayak ему соответствует

Мнемоника: байты `4e 49 43 20` в базе сервиса складываются в «NIC ».

| Роль | UUID | Свойство |
|---|---|---|
| Сервис | `9a1e0001-4e49-4320-b000-000000000000` | — |
| **Статус** | `9a1e0002-4e49-4320-b000-000000000000` | **notify** |
| **Команда** | `9a1e0003-4e49-4320-b000-000000000000` | **write** |

**Advertising разрешается кнопкой.** Mayak объявляет этот сервис **только** пока активна его кнопка ввода в эксплуатацию / тайм-аут (в обычной работе радио выключено — потребление + безопасность). Если сканирование ничего не находит, это значит «нажмите кнопку на корпусе».

### Статус (notify) — JSON с разделением по строкам

Один полный документ на строку; документ **может занимать несколько уведомлений** (собирайте по `\n`). Это отражение HEALTH/SOH, которые Mayak уже агрегирует:

```json
{"go":false,"nodes":[
  {"n":1,"bus":"nodbus","type":5,"label":"Quake","ok":false,"sensors":[
    {"id":0,"name":"ICM","h":0},
    {"id":1,"name":"ADXL355","h":2},
    {"id":2,"name":"SCL3300","h":0},
    {"id":3,"name":"RM3100","h":0}
  ]},
  {"n":2,"bus":"nodbus","type":6,"label":"Palatine","ok":true,"sensors":[
    {"id":1,"name":"AIR1","h":0},{"id":9,"name":"SOIL1","h":0}
  ]}
]}
```

- `go` — общий GO/NO-GO (все установленные датчики в порядке).
- `n` — NUMBER узла, `type` — TYPE узла, **код из собственной таблицы типов шины** (`../../core/PROTOCOL.md` §2: NodBus 1 Mayak · 2 Bifrost · 3 Argus · 4 Marconi · 5 Quake · 6 Palatine · 7 Tesla · 8 Sputnik · 9 Photon · 10 зарезервирован (Neutron) · 11 Positron · 12 Pip · 13 Steinmetz; mini 1 Gauss · 2 Quark-Tubes · 3 Pascal; ModBus 4..61, по одному на величину в позиции), а `bus` говорит, какая это таблица. Необязательное поле `label` — лишь любезность для отладки: идентичность — это код, а не имя.
- для каждого датчика: `id` = локальный номер датчика в узле (адрес в реестре Modbus или индекс датчика SPI), `name` — понятная человеку метка, `h` = **код исправности датчика**: `0` OK, `1` SELFTEST_FAIL, `2` NO_RESPONSE, `3` DEGRADED.

### Таблица поправок — задержки, которые ничем не измерить

**Всё, что станция вычитает, есть в этой таблице, и всё это принадлежит Kronos.** Одна составляющая, которую станция измерила сама, — линия часов удалённого приёмника, измеренная Kronos, — возвращается **только для чтения**, чтобы оператор видел, что найдено, а не гадал. Остальное измерить нельзя, и его приходится вводить вручную, и это **два числа**: антенный кабель в метрах и константа антенны и приёмника в наносекундах из даташита приёмника или одного стендового измерения — в той форме, которую использует принятая в мире службы времени конвенция CGGTTS (`../../kronos/FIRMWARE.md` §7, таблица задержек). Это **постоянные смещения**, поэтому их вычитают, а не терпят. Телефон — место, где их вводит человек, потому что только человек на объекте знает, сколько кабеля на самом деле протянуто.

**Kronos хранит свою копию во flash и предлагает её при старте; источник истины — центральный блок.** Поэтому приложение показывает то, во что верит станция, а запись её заменяет — заменённый Kronos получает правильные числа без того, чтобы кто-то вводил их дважды.

Чтение (в документе статуса):

```json
{"corr":{"total_ns":13150,"terms":[
  {"id":"cab","label":"antenna cable","m":20,"ns_per_m":5,"ns":100,"src":"typed"},
  {"id":"int","label":"antenna + receiver","ns":50,"src":"typed"},
  {"id":"route","label":"remoted receiver, clock run","ns":13000,"src":"ranged"}
]}}
```

- **`src` говорит, кому принадлежит число:** `typed` редактируется, `ranged` — то, что измерила станция, и оно только для чтения: запись в него отклоняется, а не молча отбрасывается.
- `m` — то, что вводит оператор; `ns` — то, что станция из этого вычислила. Составляющая, которой в сборке нет, отсутствует, а не равна нулю: `route` существует только там, где приёмник вынесен по линку Galvani (`../../galvani/README.md`, *The reversed channel*).
- Введённые составляющие суммируются и округляются на Kronos до целых циклов захвата, 7,45 ns (`../../kronos/FIRMWARE.md` §7, таблица задержек); измеренная применяется там же.
- **Линия отвода — не поправка, и в этой таблице её нет.** Карта измеряет её и записывает в блок, который размещает на ней свою собственную сетку (`../../core/PROTOCOL.md` §7); линии читаются с карт и показываются на телефоне как диагностика, по одной на слот.
- **`route` — та составляющая, которая решает, выполняет ли вынесенная сборка контракт вообще.** В стекле ~5 ns/m, так что километр — это ~5 µs против обеспечиваемой точности 1 µs. Kronos её измеряет; вынесенный приёмник, линия которого не измерена, в приложении — **NO-GO**, так же как ненастроенный датчик.

### Климатологические таблицы — задаются по стране, и страна — часть ответа

**Класс нормы не имеет смысла без таблиц, по которым он получен.** Семь вероятностных полос — от WMO и везде одинаковы; **граничные значения — это подгонка национальной службы под собственный климат**, поэтому станция несёт таблицы той страны, в которой стоит (`../../palatine/CLIMATE.md`). Ничто из этого не является константой прошивки — это конфигурация станции, вводимая один раз здесь.

Что задаёт приложение:

- **страну и обозначение службы, чьи это таблицы**, — хранятся вместе с ними, потому что всё, что публикуется с присвоенным классом, должно говорить, чьи таблицы его дали;
- **действующую норму** — 30-летний блок, отсчитываемый от 1901 года, то есть сегодня **1991–2020**. Указывается вместе с числами так же, как многолетнее среднее должно указывать свой период;
- **сами граничные таблицы** — температура в K от нормы, осадки в % от неё, по месяцам, по полугодиям (**IV–IX** и **X–III**) и за год.

**Хранит их Mayak; телефон — лишь место, где их вводят.** Это самая большая таблица, которую несёт центральный блок, и единственная, которая *не* касается собственного оборудования станции: всё остальное в этом контракте описывает корпус, а это описывает, где корпус стоит.

**Станция без загруженных таблиц всё равно измеряет и всё равно архивирует.** Она просто не классифицирует: класс — это интерпретация поверх значения, а не условие его записи. Поэтому отсутствующая таблица — не NO-GO, в отличие от неизмеренного `route`.

### Команда (write) — JSON с завершающим переводом строки

```json
{"cmd":"refresh"} // push a fresh status snapshot now
{"cmd":"recommission"} // re-run the whole commissioning pass
{"cmd":"provision","node":1} // (re)provision one node's sensors
{"cmd":"corr","set":[{"id":"cab","m":25}]}     // write one TYPED term; the station recomputes ns
                                               // a ranged term is read-only and a write is refused
```

> JSON выбран ради читаемости и потому, что ввод в эксплуатацию — редкая / эпизодическая операция. Если позже захочется компактнее, переведите обе стороны на упакованный TLV — приложение касается его только в своём парсере статуса и в своём слое BLE.

## Что нужно сборке для телефона

**Разрешения BLE**: на Android `BLUETOOTH_SCAN` (с `neverForLocation`) и `BLUETOOTH_CONNECT`, а на API < 31 `ACCESS_FINE_LOCATION`; на iOS `NSBluetoothAlwaysUsageDescription` (короткая строка «used to commission NIC stations»). Для BLE нужен настоящий телефон, а не эмулятор.

Приложение состоит из четырёх частей: GATT-контракт (UUID выше), слой BLE (сканирование, подключение, подписка на статус, запись команды), модель статуса (станция · узел · датчик, разбор JSON, словарь состояний исправности) и единственный экран.

## Дизайн — Volkov Commander

**Облик Norton / Volkov Commander:** синий DOS-фон, моноширинный шрифт, бирюзовая панель с псевдографической рамкой и фирменная **нижняя строка функциональных клавиш** (F2 Refresh · F3 Connect · F5 Recomm · F10 Quit). Никакого современного цветастого оформления — цвет — это **16-цветная палитра DOS, используемая функционально**: исправность датчиков (зелёный / жёлтый / красный), инверсная подсвечивающая полоса GO / NO-GO. Выглядит как диагностический инструмент, а не игрушка.
